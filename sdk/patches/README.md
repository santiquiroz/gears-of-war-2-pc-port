# SDK patches

Both SDK builds apply every patch here in file-name order on top of ReXGlue commit `923c1a5`:
`scripts/build-sdk.ps1` builds `rexruntime.dll` and `rexgpu-xenos.dll` from the result, and
`scripts/build-android.ps1` builds the Android libraries from its own clean clone of the same series
(`out\sdk-android-src`). Keep one change per patch file.

| Patch | What it adds |
|---|---|
| `0002-temporal-upscalers.patch` | Temporal upscaling (FSR 3.1 / FSR 4 through AMD's signed FidelityFX SDK 2.3 DLLs, DLSS on NVIDIA): jitter, motion vectors from the view-projection in the vertex constants, depth. Ported from gears-judgement-recomp; off by default (`gow2_temporal`, `gow2_upscaler`). Notes in `0002-temporal-upscalers.md`. |
| `0003-system-link-trace.patch` | System Link milestone M0/M1: `system_link_trace` logs every network and session call (`[netlink]`), unimplemented calls return defined errors, `getsockopt` works, and `setsockopt` swaps option values to host byte order (a 128 KiB receive buffer used to become 512 bytes). |
| `0004-texture-packs.patch` | Texture dump and replacement (`texture_dump`, `texture_replace`, `texture_pack_dir`): content-hashed DDS dumps in `textures/<TITLEID>/dump`, replacements (same size or larger, full mip chain) from `textures/<TITLEID>/replace`. Video planes and other textures whose content changes on every load are skipped. |
| `0005-pad-deadzone-and-file-overrides.patch` | `GOW2_VFS_OVERRIDES` lets the game read individual files from elsewhere (a cached, edited copy of the player's own Coalesced bundles) without touching the game folder, and `pad_right_stick_deadzone` gives physical controllers a radial right-stick dead zone, so the game's own look dead zone can be turned off for the mouse. |
| `0006-mnk-mouse-stick-switch.patch` | `mnk_mouse_stick` (on by default) lets the game stop the keyboard/mouse driver from turning mouse motion into right-stick deflection while it keeps the mouse captured, so the port can hand the mouse to the game's own PC mouse path instead. |
| `0007-android-arm64-port.patch` | The Android arm64 port of the runtime (NDK r29+, API 29). Build: an `android-arm64` platform, no `-march=armv8-a` that would lower the game's `armv8.2-a`, SDL3 as the shared `libSDL3.so` SDLActivity loads (no X11/Wayland/ALSA), `SDL_main` from `windowed_app_main_sdl.cpp`, Vulkan from the system `libvulkan`, the SDK version read from the SDK's own git history under `add_subdirectory`. Core: `GetAndroidApiLevel()` (`main_android`), guest memory through `ASharedMemory` with a `memfd_create` fallback (no `/dev/ashmem`), Bionic fixes (64-bit `off_t`, no robust mutexes, `clock_cast`, and `"a+"` streams rewound after opening: Bionic starts their reads at the end of the file, so the Vulkan shader and pipeline storage found no header and truncated itself on every launch), an AArch64 fiber switch that keeps the callee-saved x19-x28, fp, lr and d8-d15 (Bionic has no `ucontext`), unclaimed `SIGSEGV`/`SIGBUS`/`SIGILL` chained to the previous handler instead of looping, `REX_EXECUTABLE_FOLDER` for config and logs, `content://` stubs. UI: an `ANativeWindow` surface from the SDL window. The GPU plugin is loaded by name from the APK. Input: one recursive lock across the `InputSystem` entry points and a non-throwing `utf8::next` (the Windows build gets both from the port's own guards). `XnAddrStatus` constants get definitions. Guest sockets: ports 1-1023 bind 30000 higher (apps may not bind them), and `SOL_SOCKET` options and `FIONBIO`/`FIONREAD` with Winsock numbers are translated. Touch: the SDL window delivers finger events as `TouchEvent` and drops the mouse events SDL synthesizes from fingers and pens, an `ImGuiDialog` can say it does not need repainting at the display's refresh rate (`WantsContinuousPaint`), and the ImGui drawer releases a touch whose lift arrived before any frame saw the press one frame later, so a quick tap on the settings overlay is a click. Vulkan diagnostics: `vulkan_android_stats_log` logs the command processor's work every five seconds (`GPUSTATS`: swaps, draws by kind, depth formats, depth tests of color draws, render passes and why they ended, submissions, queue drains, occlusion queries, pipeline setup time, texture bindings without the image their texture uses, user clip planes and vertex kill, guest memory uploads by the draw step that needed them, CPU invalidations, texture loads, those of ranges a resolve or memexport wrote (`gpu_written`, not checked for zero: their data lives only in the GPU's copy of guest memory) and all-zero texture data of the rest with `TEXZERO` lines, depth-only float24 draws with no color target 0) and each texture format once (`TEXFMT`); a texture whose data cannot be loaded is always logged once per format (`TEXFAIL`). `vulkan_android_trace_frame_after_seconds` logs every draw of one frame (`FRAMETRACE`; `FRAMETRACE-STATE` with the render pass key, surface, depth and written color targets, viewport, window scissor and polygon offset; `FRAMETRACE-VERTS` with the first three vertices of rectangle lists; `FRAMETRACE-RT` with the render target ownership transfers, resolves and resolve clears, numbered by the next draw). Vulkan switches for the experiments of `docs/ANDROID_EXPERIMENTS.md`, keeping today's behaviour by default except `vulkan_android_color_depth_bias` (below): `vulkan_android_empty_fragment_shader`, `vulkan_android_invariant_position_member`, `vulkan_occlusion_query_precise`, `vulkan_async_pipeline_placeholders` (on), the diagnostic bits of `vulkan_android_depth_experiment` (1-1024), `vulkan_android_color_depth_bias`, `vulkan_android_skip_shader_hashes`, `vulkan_android_paint_shader_hashes` and `vulkan_android_skip_draw_range`; their decisions are plain functions in `include/rex/graphics/vulkan/android_draw_experiments.h`, checked by `tests/unit/graphics/android_draw_experiments_test.cpp`. `vulkan_android_color_depth_bias` defaults to 16 on Qualcomm GPUs (Vulkan vendor ID `0x5143`) unless set and to 0 on other GPUs (`ResolveColorDepthBias` in the same header); 16 units are 16 float32 ULPs of the D32 host depth (float24 is hosted as `D32_SFLOAT_S8_UINT`), about 2 float24 steps, while the measured prepass/base-pass depth mismatch is up to about one float24 step; the runtime logs `Android: color depth bias 16 (GPU vendor 0x5143, default for this vendor)`. The Vulkan render target transfer shader now addresses the host depth source with its own sample count rather than `key.source_msaa_samples` (a 2x MSAA source and 1x host depth source previously read `8 * tile_row + y` instead of `16 * tile_row + y`, with no visible change at this checkpoint), and `ANativeWindow_setFrameRate` is looked up through `dlopen("libnativewindow.so")` then `dlsym`, falling back to `libandroid.so` (to be confirmed on the phone). FPSCR: the guest rounding mode reads back right on ARM. `FPSCRRegister::loadFromHost` takes each host's own table (`FPSCRRoundingX64` and `FPSCRRoundingArm64` in `include/rex/platform/fpscr.h`, both defined on every host, the x64 values unchanged): FPCR.RMode orders +infinity and -infinity unlike MXCSR.RC, so `mffs` used to read Up as Down and Down as Up on the phone, and the game's read-modify-write of the FPSCR (`mffs`, `or`, `mtfsf 255`) flipped a directed rounding mode there. `static_assert`s and `tests/unit/ppc/fpscr_rounding_test.cpp` (run by `scripts/test-host.ps1`) check both tables. `clear_memory_page_state` defaults to off on Android: re-uploading every CPU-written page at each frame end ended a Vulkan render pass per upload and halved Gears of War 2's frame rate on the Adreno 830. FFmpeg runs its C code: `thirdparty/ffmpeg-android/config.h` comes before FFmpeg's own `config.h` and turns the aarch64 assembly off, so the FFmpeg submodule is not modified. Present effects: Android uses the FSR 1 / CAS SPIR-V already in the tree, with `REX_HAS_FIDELITYFX_SDK` defined for `rexui` without fetching FidelityFX. `present_effect` defaults to `fsr` and accepts `bilinear`, `cas`, `fsr` and `sgsr`; at launch only the selected effect's shader modules and pipelines are created (bilinear is always available). A rejected shader module or pipeline makes that effect unavailable with one warning, and painting falls back to bilinear with one warning; SGSR 1 is never an intermediate pass. `present_fsr_sharpness_reduction` defaults to 0.3 stops and `present_dither` is on (not applied with `sgsr`). `sgsr` is Snapdragon GSR 1, a one-pass shader in `src/ui/shaders/sgsr/` with Qualcomm's LICENSE beside it; `src/ui/shaders/vulkan_spirv/guest_output_sgsr1_ps.h` holds its SPIR-V, made with the NDK's `glslc`. Vulkan presenter (Vulkan only, not compiled on Windows): one present semaphore per swapchain image is signaled by its paint submission and awaited by the present of that same image; retired swapchain semaphores are destroyed with it, fixing `VUID-vkQueueSubmit-pSignalSemaphores-00067`. The final pass's swapchain pipeline records the format it was built for, avoiding a wait for the prior paint submission and rebuilding the pipeline on every paint. Display: FIFO by default; `present_android_frame_rate` defaults to 30 Hz, requested through `ANativeWindow_setFrameRate` on Android 11+ (0 asks for nothing). Driver pipeline cache: `vulkan_pipeline_cache_file` defaults to on and keeps `<title>.vkpc` beside the shader storage, validating the vendor, device, driver version, pipeline cache UUID, size and XXH3 hash before loading; it saves after boot-time pipelines, every two minutes while new pipelines appear, and at shutdown, through a `.tmp` file then rename. Its format is in `include/rex/graphics/vulkan/pipeline_cache_file.h`, checked by `tests/unit/graphics/pipeline_cache_file_test.cpp`. CPU waits: `gpu_worker_spin_us` defaults to -1 on Android, keeping the SDK's 500 `sched_yield` polls; 50 is available for 50 microseconds of polling with ISB pauses before sleeping on the write pointer event in 5 ms waits, and 0 sleeps at once. Every change is behind `ANDROID` / `REX_PLATFORM_ANDROID` / `__ANDROID__`, except the Vulkan transfer shader line and Vulkan presenter fixes (Vulkan only, not compiled on Windows), the FPSCR tables (the same x64 values), the header-only unit tests, and the pure header `pipeline_cache_file.h` and its test (both platform-neutral), so Windows behaves as before. |

Sockets: `sendto`/`recvfrom` addresses in network order (port 1000 no longer leaves as 59395), `from` written only on success, guest WSA error codes from `sendto`, `setsockopt` and `bind`, `SIO_UDP_CONNRESET` off on Windows UDP sockets, `getsockname` implemented (the engine binds its game socket to port 0 and reads the port back; without it every join failed), and `net_traffic_log_sec` logs bytes and packets per peer. | `0011-network-crossplay.patch` | System Link milestone M2b (`docs/COOP_N_PLAYERS.md`, Stage 4 networking), on top of the opt-in 0010. Its network settings do nothing until `net_link_active` is on, but the port remap and the POSIX socket fixes apply with the link off too (Android cannot bind port 1000 even in a solo game), so a solo game binds UDP 0.0.0.0:41000 where retail bound 1000. Port remap: guest ports below 1024 use port + `net_port_offset` on the host (default 40000, so the game's UDP 1000 becomes 41000; beacon port 14001 is unchanged), applied symmetrically in bind, connect, sendto, recvfrom, accept, getsockname and getpeername; its `getsockname` replaces 0010's (the same export, now with the port mapped back and the guest's name length checked), and `getpeername` is a real export now (it was a stub returning WSAEOPNOTSUPP). POSIX sockets (Android, Linux): Winsock option numbers map to the host's through one table that `setsockopt` and `getsockopt` share; SO_LINGER reads as two big-endian 16-bit fields (this also fixes Windows, where the old 32-bit swap exchanged on/off and the timeout); `ioctlsocket` FIONBIO sets O_NONBLOCK and FIONREAD returns the count big-endian (Windows returned it little-endian before); `select` computes nfds from the host descriptors (the game passes 0); errno maps to WSA codes, and every socket call keeps its own error in a per-thread slot right after the host call fails. Internet play: `net_peers` (a comma-separated host[:port] list, IPv4 or DNS names) gets a unicast copy of every broadcast; `net_public_address` is advertised as XNADDR inaOnline/wPortOnline; `net_allow_peers` filters inbound datagrams (loopback and the local subnet always pass); with it empty and `net_peers` or `net_public_address` set, only the peers and the local subnet pass, and an unresolved name lets nothing in. DNS names resolve on one background thread every 5 minutes and keep their last good addresses when a lookup fails. `XNetXnAddrToInAddr` returns ina for local peers and inaOnline for the rest. Every 0011 setting joins 0010's read-once snapshot (restart to change); the game threads never read cvar strings. A broadcast from the beacon socket (guest port 14001) also goes as a unicast copy to the senders heard on it in the last second, at most 4 per broadcast and 2 per second per sender, with a 250 ms duplicate filter; on Android and Linux 255.255.255.255 goes out as the subnet's directed broadcast, and Windows sends both. Datagram sockets receive into a 64 KiB host buffer and check the source before copying into guest memory (an oversized allowed datagram is truncated with WSAEMSGSIZE); stream sockets skip the datagram filters. `net_local_ip` accepts a.b.c.d or a.b.c.d/prefix (prefix 24 by default); empty means `REX_DETECTED_LOCAL_IP`, then `net_bind_ip`, then 0010's routed address, then 127.0.0.1. `[netlink]` logging covers the settings, every remap, drop, fan-out and DNS pass; the first datagram per socket and peer in each direction is always logged (`first datagram from/to ...`), and successful and failed `recvfrom`/`sendto` calls have separate trace budgets. 0010's `net_traffic_log_sec` counts the datagrams that pass these filters into guest memory and every unicast copy sent, by host address and port (41000, not 1000). Unit tests in `tests/unit/system/system_link_test.cpp` (`scripts/test-host.ps1`). It replaces 0007's Android-only port shift (+30000), option translation and FIONBIO/FIONREAD code in `src/system/xsocket.cpp`, so a phone and a PC both use 41000; SO_KEEPALIVE and SO_OOBINLINE join its option table. |
| `0012-coop-beacon-gate.patch` | Co-op beacon gate for 3+ players (`docs/COOP_N_PLAYERS.md`, Stage 4 version gate). The game sets `net_coop_hash` (a new UINT64 cvar, 0 by default) to the combined hash of its co-op patch groups when `gow2_coop_players` is 3 or more; it reaches the runtime through `rex::cvar::SetFlagByName`, because the game links the prebuilt SDK and only swaps in this DLL. With a hash set, every datagram the System Link beacon socket (guest port 14001) sends is preceded by a 17-byte hello (`GOW2HELO`, version 1, the hash big-endian) to the same address, and a beacon datagram is accepted only from a source whose hello in the last 5 s carried the same hash; hellos never reach the guest, a dropped source gets our hello back (at most one per second) so both sides log the mismatch (`[netlink] beacon from ... dropped: ...`, `[netlink] co-op hash from ... is ..., ours is ...`). Mismatched peers never see each other's campaign. With no hash (the retail two-player default) nothing changes. `net_beacon_gate` (default true) turns the check off. Pure helpers (`EncodeBeaconHello`, `ParseBeaconHello`, `BeaconHellos`, `JudgeBeaconDatagram`, `FormatCoopHash`) are tested in `tests/unit/system/system_link_test.cpp`. |
| `0013-host-ui-hooks.patch` | Host UI hooks for the in-game PC Options menu ([docs/PC_OPTIONS.md](../../docs/PC_OPTIONS.md)). `xam_input_block` gives the game a neutral pad and no keystrokes while a host menu is open, and the storage device selector call with the UI flag (0x200) runs the command cvar `xam_device_selector_ui_command` as a system UI instead of the headless pick; the boot-time call stays headless. The routing helper is tested in `tests/unit/kernel/host_ui_route_test.cpp`. |
| `0014-fault-report.patch` | Crash reports a player can send. On Android, a fault no guest handler claims logs one `FAULT unclaimed` line before it is chained to the previous handler: the signal and its `si_code` (SIGSEGV vs SIGBUS tells an unmapped page from shared memory the kernel could not provide), `si_addr`, the faulting `pc` and the `lr` as `module+offset` through `dladdr` (map them with the unstripped `libgow2.so` of the same build), the ESR and the thread. On every platform an unhandled guest access violation adds a second line with the guest page that faulted: its heap and page size, reserve/commit state, protection and the allocation around it, so a game write past its own allocation reads differently from a host page that failed. Logging only; nothing else changes. |
| `0015-old-kernel-fixed-mappings.patch` | Guest memory on Linux and Android kernels older than 4.17 (Snapdragon 845 phones ship 4.9). `AllocFixed` maps fixed addresses with `MAP_FIXED_NOREPLACE` and relies on `EEXIST` to commit inside an existing reservation with `mprotect`; older kernels do not know the flag, treat the address as a hint and return a mapping somewhere else, which was taken as success, so the guest page stayed inaccessible (issue #1: the first guest thread stack, `XThread::AllocateStack`, faulted with `SEGV_ACCERR` on a page the guest heap had committed read-write). A mapping that lands anywhere but the requested address is now unmapped and handled as `EEXIST`. The same cause and fix were found for Burnout Paradise on ReXGlue (shipa-2/Xerenge#4). |
| `0016-turnip-no-sparse-by-default.patch` | Shared memory without sparse binding on Mesa Turnip unless the player sets `vulkan_sparse_shared_memory` (issue #1: a recent Turnip on an Adreno 630 advertises sparse binding but every `vkQueueBindSparse` fails, then every presenter submission fails; an older Turnip without sparse binding uses the full 512 MB buffer and boots). The player's own value always wins; Qualcomm's drivers keep sparse binding. The choice is the pure `UseSparseSharedMemory` in `src/graphics/vulkan/shared_memory.cpp`, and the runtime logs when Turnip turns it off. |
| `0017-d3d12-stats-log.patch` | Windows performance counters, off by default: `d3d12_stats_log` logs one `D3D12STATS` line every five seconds with frames, draws, draws skipped while their pipeline is pending, shaders translated on the draw thread vs on worker threads, pipelines created, guest memory uploads and bytes, memexport readbacks (fast and full path) and the time spent waiting for them, texture loads and allocations, and GPU queue waits with their time. Counters are relaxed atomics behind one cvar check (`src/graphics/d3d12/performance_stats.h`). Pairs with the game's `gow2_frame_log` (`FRAMESTATS`: fps and frame-time percentiles), now on Windows too. |
| `0018-gpu-backend-cvar.patch` | `gpu_backend` selects `any` (the default), `d3d12` or `vulkan` when loading the GPU plugin. | `0019-vulkan-texture-exponent-bias-word.patch` | The Vulkan shader translator read a texture fetch's result exponent bias (`exp_adjust`, fetch constant word 3 bits 13:18) from word 4, whose bits 12:21 are the LOD bias, so every texture the game sampled with a LOD bias (textures still streaming in, freshly loaded weapons, objects coming into view, the title-screen lightning) was multiplied by up to 2^31 and drawn white for a moment; it now reads word 3 like the D3D12 translator. Fixes the white objects on Android and on Windows Vulkan (verified on an RX 7800 XT, 2026-10-19). |
| `0020-vulkan-resolve-write-barrier.patch` | Shared memory usage `kComputeWrite` (unscaled resolves write guest memory from a compute shader) now includes `VK_ACCESS_SHADER_WRITE_BIT`, so the barrier before a later read covers those writes, as the D3D12 UAV barrier does. |
| `0021-d3d12-host-vsync.patch` | The D3D12 presenter always presented with sync interval 0 and tearing allowed, so `vsync = true` only paced the guest and the picture still tore on high refresh rate screens without variable refresh rate (a tester's handheld). With `vsync` on it now presents with sync interval 1 and no tearing; with it off it keeps presenting at once with tearing allowed. |
| `0022-mnk-keys-switch.patch` | `mnk_keys` (default true). Off, the keyboard no longer drives the emulated pad buttons and sticks, so a game that reads keys itself does not get them twice; the mouse and its capture are not affected (the port turns it off during gameplay, when it reads keys itself). |
| `0023-texture-variants.patch` | Texture pack variants. `texture_replace_variant` (default empty) names a folder `<TITLEID>/replace_<variant>` whose files win over `replace/` while it is set; changing it reloads, at the next submission, the textures that wear a replacement or that the variant has a file for, so a game can swap art at run time (the port shows keyboard or pad pictures this way). Unit-less: checked in the game (`[texpack] variant` log lines, the swapped texture). |

## Working on a patch

Each patch lives in a git worktree of rexglue-sdk based on `923c1a5` plus the patches before it.
After editing, `scripts/verify-sdk-patch.ps1 -Worktree <worktree>` applies the worktree's changes to
the prepared build tree and compiles both DLLs in seconds; then regenerate the patch with
`git diff --binary HEAD > sdk/patches/<name>.patch` and run `scripts/build-sdk.ps1`.

The Android port is worked on in a worktree of `923c1a5` with 0002-0007 applied and nothing after
them (committed or not; only the files count). Build it with `scripts/build-android.ps1 -SdkSource <worktree>`, then regenerate
0007 as the difference between `923c1a5` plus 0002-0006 and the worktree, using a temporary index so
the worktree's own index and commits stay as they are. A worktree that also carries 0008 or later
would fold those patches into 0007, and applying them after it would then fail; the recipe takes
them back out of `$port` first (Git Bash, from the worktree):

```sh
patches=/c/path/to/gow2-recomp/sdk/patches
export GIT_INDEX_FILE=$(mktemp -u)
git read-tree 923c1a5
for p in "$patches"/000[2-6]-*.patch; do git apply --cached "$p"; done
base=$(git write-tree)
git read-tree HEAD && git add -A
for p in $(ls "$patches"/*.patch | sort -r); do   # 0008 and later, newest first
  case $(basename "$p") in 000[2-7]-*) continue ;; esac
  git apply --cached -R --check "$p" 2>/dev/null && git apply --cached -R "$p"
done
port=$(git write-tree)
rm -f "$GIT_INDEX_FILE"; unset GIT_INDEX_FILE
git diff --binary "$base" "$port" > "$patches/0007-android-arm64-port.patch"
```

`scripts/build-android.ps1` runs this comparison itself before every build, for `-SdkSource` and for its own clone, and lists the paths that differ. Check that the series still reproduces the worktree: applying 0002-0007 with `git apply --cached`
to a temporary index read from `923c1a5` must give the same `git write-tree` as `$port`.
Then check the whole series: every patch from 0002 to the last one must apply in order on that index.

`scripts/build-sdk-android.ps1` builds the SDK alone for Android (bring-up); see `docs/ANDROID.md`.
